End-to-End: Perjalanan Finansial Andi Pratama (Mei 2025)

Konteks Awal & Logika Otomasi

  • User: Andi Pratama (Mahasiswa Semester 3)
  • Pemasukan: Rp 500.000 / minggu (Uang Saku)
  • Tujuan: Disiplin anggaran dan menabung untuk Laptop Rp 8.000.000.
  • Sistem Flow: Auto-alokasi berjalan berdasarkan konfigurasi awal. Andi menetapkan persentase alokasi di awal, sehingga setiap kali ada pemasukan masuk, sistem dapat memecah dan memasukkannya ke kategori yang tepat secara otomatis.

FASE 1: ONBOARDING & AUTENTIKASI (4 Mei 2025)

Malam itu, Andi yang baru saja naik ke semester 3, merasa uang saku mingguannya selalu habis tanpa jejak yang jelas. Setelah browsing mencari solusi, ia menemukan dan mengunduh aplikasi FAST. Ia merebahkan diri di kasur kosannya, membuka aplikasi tersebut, dan memutuskan untuk langsung membuat akun baru menggunakan email kampus agar terlihat lebih rapi dan profesional.

1. UC-01: Registrasi via Email

Andi mengisi form pendaftaran. Frontend melakukan enkripsi dasar dan mengirim payload ke Backend.

// [POST] /api/v1/auth/register
// Request Payload
{
  "name": "Andi Pratama",
  "email": "andi.pratama@mahasiswa.ac.id",
  "password": "Andr@2025!", // Backend akan hash menggunakan bcrypt (Cost: 12)
  "device_id": "android-pixel5-abc"
}

// Response (201 Created)
{
  "status": "success",
  "data": {
    "user": {
      "id": 1,
      "name": "Andi Pratama",
      "email": "andi.pratama@mahasiswa.ac.id",
      "created_at": "2025-05-04T19:30:00Z"
    },
    "tokens": {
      "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6...",
      "expires_in": 3600
    }
  }
}

(Catatan: Jika Andi menggunakan UC-02 Registrasi Google, aplikasi akan memanggil API Google OAuth, menukar auth_code dengan profil user, dan mengembalikan struktur token yang sama tanpa menyimpan password).

FASE 2: SETUP FONDASI & TARGET TABUNGAN (5 Mei 2025)

Keesokan paginya, saat sedang duduk di kantin menunggu kelas Algoritma Pemrograman dimulai, Andi memikirkan impian besarnya. Ia sangat membutuhkan laptop baru dengan performa lebih tinggi untuk mengerjakan tugas coding yang semakin berat. Menggunakan waktu senggangnya, Andi mulai mengatur fondasi finansialnya di aplikasi FAST. Ia ingin mendisiplinkan diri dengan mengatur "aturan main" keuangan sebelum ada uang yang masuk, sehingga sistem bisa mengotomasikan alokasinya nanti.

2. UC-07: Atur Alokasi Anggaran & UC-08: Rekomendasi Alokasi

Andi mengatur alokasi mingguan menggunakan aturan 50/30/20. Backend menjalankan UC-08 untuk memvalidasi apakah persentase ini sehat.

// [POST] /api/v1/budgets/allocation
// Request
{
  "period": "weekly",
  "allocations": [
    { "category": "Kebutuhan Pokok", "percentage": 50.0 },
    { "category": "Hiburan", "percentage": 30.0 },
    { "category": "Tabungan", "percentage": 20.0 }
  ]
}

// Response (200 OK) - Termasuk hasil evaluasi UC-08
{
  "status": "success",
  "recommendation": {
    "is_healthy": true,
    "is_healthy": true,
    "message": "Alokasi 50/30/20 sangat ideal untuk profil mahasiswa."
  }
}
3. UC-11: Buat Target Tabungan & UC-12: Progress Bar

Andi memasukkan impiannya membeli laptop. Sistem langsung mengkalkulasi estimasi waktu pencapaian berdasarkan alokasi 20% dari estimasi pemasukan rata-rata mingguan.

FASE 3: ARUS KAS & OTOMASI SISTEM (5 Mei 2025)

4. UC-05: Catat Pemasukan

Siang harinya, layar ponsel Andi menyala menampilkan notifikasi SMS banking: uang saku mingguan dari orang tuanya telah masuk sebesar Rp 500.000. Sambil berjalan menuju perpustakaan, Andi dengan cepat membuka aplikasi FAST dan mencatat pemasukan pertamanya minggu ini. Ia tersenyum lega mengetahui bahwa ia tak perlu lagi pusing membagi-bagi uangnya secara manual.

// [POST] /api/v1/transactions/income
{
  "amount": 500000.0,
  "category": "Uang Saku",
  "date": "2025-05-05T10:00:00Z"
}
⚙️ SYSTEM LOGIC (Background Processing):

Sistem mendeteksi adanya income baru dan mengeksekusi trigger secara internal:

  • Distribusi Anggaran (UC-07): Kebutuhan Pokok +Rp 250.000, Hiburan +Rp 150.000, Tabungan +Rp 100.000.
  • Distribusi Tabungan (UC-11): Saldo Tabungan Rp 100.000 otomatis dimasukkan ke target "Laptop Baru". (Progress naik menjadi 1.25%).

FASE 4: TRANSAKSI PENGELUARAN (5 - 6 Mei 2025)

5. UC-06 Skenario A: Catat Pengeluaran Manual

Sore harinya setelah jadwal kuliah padat usai, Andi mampir ke minimarket Alfamart di dekat gerbang kampus. Ia membeli beberapa kebutuhan dasar seperti sabun, air mineral, dan roti untuk sarapan besok. Tepat setelah membayar di kasir, ia berdiri sejenak di depan pintu keluar, lalu langsung mencatat pengeluaran receh tersebut secara manual ke dalam aplikasi agar tidak lupa.

6. PIPELINE OCR (UC-13 hingga UC-17)

Keesokan harinya (Selasa), Andi dan teman-teman sekelasnya makan siang bersama di Warung Bu Sari yang letaknya persis di belakang area parkir motor. Merasa malas jika harus mengetik panjang lebar nama menu dan harganya satu per satu, Andi meminta struk cetak dari kasir warung. Ia mengarahkan kamera ponselnya ke struk tersebut, memfotonya, dan membiarkan sistem OCR Cloud Vision serta keajaiban klasifikasi Gemini AI yang bekerja keras mengekstrak daftar makanannya.

// [GET] /api/v1/ocr/result/9921 (Hasil Draft pipeline UC-14 s/d UC-16)
{
  "status": "ready_for_review",
  "data": {
    "store_name": "Warung Bu Sari",
    "date": "2025-05-06",
    "total_amount": 27000.0, // OCR salah baca angka 5 jadi 0

      { "name": "Es Teh Manis", "price": 5000.0, "ai_category": "Kebutuhan Pokok" } // Salah harga
    ]
  }

Andi melakukan validasi manual (UC-17) untuk mengoreksi harga Es Teh menjadi 5500 dan menyimpannya.

Skenario Perjalanan Andi Pratama

Andi Pratama, mahasiswa semester 3 Teknik Informatika, menggunakan sistem FAST untuk mengelola uang saku mingguan Rp 500.000. Perjalanan dimulai dari registrasi (UC-01), pengaturan alokasi 50/30/20 (UC-07), hingga penetapan target tabungan Laptop baru Rp 8jt (UC-11). Setiap transaksi dicatat secara manual (UC-06A) atau via OCR (UC-13) untuk efisiensi. Sistem secara otomatis membagi pemasukan ke pos anggaran dan tabungan, memberikan peringatan jika Andi overspend di kategori Hiburan (UC-10), dan memberikan insight cerdas via Gemini AI (UC-20) untuk memastikan Andi tetap disiplin mencapai target laptopnya di Desember 2026.

Keterangan Struktur Andi Pratama Version

Diagram kelas ini mencerminkan arsitektur sistem FAST yang digunakan dalam narasi perjalanan Andi Pratama:

1. Sinkronisasi Narasi (Bulan Mei 2025)
  • User: Entitas Andi Pratama dengan email kampus.
  • SavingGoal: Target khusus "Laptop Baru" Rp 8jt dengan alokasi 20%.
  • Dashboard: Titik pusat pemantauan mingguan Andi (UC-18).
2. Pipeline Data & AI
  • OCR Pipeline: Proses dari Receipt hingga OCRResponse (UC-13 s/d UC-17).
  • AI Insight: Hasil analisis Gemini API terhadap pengeluaran Andi (UC-20).
  • Financial Profile: Rekapitulasi perilaku Andi (Top Category, OCR usage 57%).
Skenario Integrasi Andi Pratama

  1. Input Awal: Budi mengunggah foto struk senilai Rp 150.000. Data masuk ke entitas Receipt.
  2. Komunikasi OCR: Kelas Receipt memicu metode process_ocr() yang menggunakan OCRResponse. Di sini terjadi relasi Dependensi di mana satu kelas menggunakan layanan kelas lain untuk validasi.
  3. Pembentukan Item: Melalui relasi Komposisi, sistem secara otomatis membuat beberapa entitas ReceiptItem (misal: Nasi Ayam, Jus Jeruk). Karena ini komposisi, jika Receipt dihapus, maka ReceiptItem tersebut juga akan hilang.
  4. Sinkronisasi Transaksi: Data yang sudah valid kemudian "mengalir" menjadi entitas Transaction. Hubungan Asosiasi memastikan transaksi ini tercatat atas nama User (Budi).
  5. Update Real-time: Transaction baru ini secara otomatis memicu metode update_balance() pada BudgetRemaining untuk memotong kuota anggaran makan siang Andi hari itu.
